# 测试与持续集成

本文面向 FastAPI + PostgreSQL 后端项目，目标是建立一套能长期维护的测试体系，而不是追求覆盖率数字。

## 1. 测试分层

| 层级 | 测试对象 | 速度 | 外部依赖 |
|---|---|---|---|
| 单元测试 | 纯函数、领域规则 | 很快 | 无 |
| 服务层测试 | 业务逻辑、事务边界 | 快 | 数据库 |
| API 集成测试 | 路由、依赖、请求响应 | 中 | 应用 + 数据库 |
| 外部集成测试 | Redis、RabbitMQ、S3 | 慢 | 外部服务 |
| 端到端测试 | 真实用户路径 | 慢 | 完整环境 |

推荐比例：

``` text
大量单元测试
适量服务层和 API 测试
少量外部集成和端到端测试
```

不要为简单 getter/setter 写无意义测试。测试应该保护业务规则、边界条件和回归风险。

## 3. 单元测试

单元测试只测一个明确行为。

``` python
import hashlib


def sha256_bytes(content: bytes) -> str:
    return hashlib.sha256(content).hexdigest()


def test_sha256_bytes_returns_hex_digest():
    result = sha256_bytes(b"hello")
    assert result == "2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824"
```

好的单元测试命名：

``` text
test_计算文件摘要
test_文件超过限制时抛出异常
test_用户无权限时拒绝访问
```

每个测试遵循：

``` text
Given 前置状态
When 执行动作
Then 断言结果
```

## 4. 数据库测试与事务回滚

服务层和 API 测试应尽量接近真实数据库行为，避免完全 Mock SQLAlchemy。

### 4.1 测试数据库

不要在生产数据库上跑测试。推荐使用独立测试数据库：

``` bash
TEST_DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/app_test
```

可以在测试启动前创建独立库，测试结束后删除，或使用固定测试库加数据回滚。

### 4.2 异步数据库 fixture

``` python
import pytest
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine, async_sessionmaker
from sqlalchemy.orm import clear_mappers

from app.models import Base


@pytest.fixture
async def db_session():
    engine = create_async_engine(TEST_DATABASE_URL, echo=False)
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.drop_all)
        await conn.run_sync(Base.metadata.create_all)

    factory = async_sessionmaker(engine, expire_on_commit=False)
    async with factory() as session:
        yield session
        await session.rollback()

    await engine.dispose()
```

`drop_all/create_all` 适合小项目。真实项目建议使用 Alembic 建表，确保测试环境和生产迁移一致。

### 4.3 事务回滚策略

另一种更快的方案：

1. 开启外层事务。
2. 测试内的 commit 变成外层事务的一部分。
3. 测试结束后回滚外层事务。

这种方式可以保持测试之间隔离，但实现复杂。初学者先用“独立数据库 + 每个测试重建数据”，理解成本更低。

### 4.4 fixture 生命周期

``` python
@pytest.fixture
async def tenant(db_session):
    tenant = Tenant(name="test-tenant")
    db_session.add(tenant)
    await db_session.commit()
    return tenant


@pytest.fixture
async def user(db_session, tenant):
    user = User(email="user@example.com", tenant_id=tenant.id)
    db_session.add(user)
    await db_session.commit()
    return user
```

fixture 应表达业务前置状态，而不是到处在测试内重复造数。

## 5. FastAPI API 测试

使用 `ASGITransport`，不需要真实端口。

``` python
from httpx import ASGITransport, AsyncClient
import pytest

from app.main import app


@pytest.fixture
async def client():
    transport = ASGITransport(app=app)
    async with AsyncClient(transport=transport, base_url="http://test") as client:
        yield client
```

测试创建接口：

``` python
@pytest.mark.api
async def test_create_document_returns_201(client, auth_headers):
    response = await client.post(
        "/documents",
        headers=auth_headers,
        json={"title": "Security Guide"},
    )

    assert response.status_code == 201
    assert response.json()["title"] == "Security Guide"
```

测试错误路径：

``` python
@pytest.mark.api
async def test_create_document_rejects_blank_title(client, auth_headers):
    response = await client.post(
        "/documents",
        headers=auth_headers,
        json={"title": ""},
    )

    assert response.status_code == 422
```

### 5.1 必测 API 场景

- 成功创建
- 参数校验失败
- 未登录
- 无权限
- 资源不存在
- 唯一冲突
- 并发冲突
- 分页和排序
- 错误响应格式

## 6. Mock 外部服务

### 6.1 什么时候 Mock

适合 Mock：

- 邮件服务
- 短信服务
- LLM API
- 支付网关
- 文件病毒扫描

不建议 Mock：

- 数据库
- ORM 查询本身
- Alembic 迁移
- Redis 关键行为

过度 Mock 会测试“实现细节”，重构即失败。

### 6.2 依赖注入替换

``` python
from app.services.virus_scanner import VirusScanner


class FakeVirusScanner(VirusScanner):
    def __init__(self, infected: bool = False):
        self.infected = infected

    async def scan(self, content: bytes) -> bool:
        return self.infected


def test_upload_rejects_infected_file(fake_virus_scanner):
    scanner = FakeVirusScanner(infected=True)
    assert scanner.scan(b"bad") is True
```

FastAPI 中可以用 `dependency_overrides`：

``` python
from app.deps import get_virus_scanner


@pytest.fixture
async def infected_client(app):
    app.dependency_overrides[get_virus_scanner] = lambda: FakeVirusScanner(True)
    transport = ASGITransport(app=app)
    async with AsyncClient(transport=transport, base_url="http://test") as client:
        yield client
    app.dependency_overrides.clear()
```

### 6.3 HTTP Mock

``` python
import respx
from httpx import Response


@respx.mock
async def test_notify_service_failure_is_handled(http_client):
    respx.post("https://example.com/notify").mock(
        return_value=Response(500, json={"error": "unavailable"})
    )

    result = await notify_user(user_id=1)
    assert result.status == "notify_failed"
```

外部故障必须被测试覆盖，否则线上抖动会变成业务数据不一致。

## 7. 数据工厂与测试数据

避免每个测试手写大量字段。

``` python
import factory


class UserFactory(factory.Factory):
    class Meta:
        model = User

    email = factory.Sequence(lambda n: f"user{n}@example.com")
    password_hash = "$argon2id$..."
    is_active = True
```

测试数据原则：

- 使用明显虚构邮箱和域名。
- 时间使用固定 UTC 时间，避免时区问题。
- 测试之间不要依赖执行顺序。
- 不要依赖数据库自增 ID。
- 敏感数据不进入 fixture。

## 8. 覆盖率与质量门禁

安装：

``` bash
uv add --dev coverage pytest-cov
```

运行：

``` bash
pytest --cov=app --cov-report=term-missing --cov-report=xml
```

关注重点：

``` text
业务规则
权限判断
事务边界
错误处理
迁移
并发路径
```

不要为了覆盖率写重复断言。覆盖率是发现未测试代码的工具，不是质量证明。

建议门槛：

``` text
单元 + 服务 + API 测试全部通过
关键模块行覆盖率 >= 80%
分支覆盖率关注核心业务 >= 70%
禁止新代码覆盖率显著下降
```

## 9. GitHub Actions

``` yaml
name: backend-ci

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:17
        env:
          POSTGRES_USER: postgres

          POSTGRES_DB: app_test

          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 5s
          --health-timeout 3s
          --health-retries 10

    env:
      DATABASE_URL: postgresql+asyncpg://postgres:postgres@localhost:5432/app_test
      JWT_PRIVATE_KEY: ${{ secrets.JWT_PRIVATE_KEY }}
      JWT_PUBLIC_KEY: ${{ secrets.JWT_PUBLIC_KEY }}

      - uses: actions/checkout@v4

      - name: Install uv
        uses: astral-sh/setup-uv@v5

      - name: Install dependencies
        run: uv sync --frozen

      - name: Run migrations
        run: uv run alembic upgrade head

      - name: Run tests
        run: uv run pytest --cov=app --cov-report=xml

      - name: Upload coverage
        uses: actions/upload-artifact@v4
        with:
          name: coverage
          path: coverage.xml
```

## 10. 修复失败的测试

遇到测试失败：

1. 阅读失败断言，不要猜。
2. 复现最小输入。
3. 判断是业务代码错误、测试数据错误，还是环境问题。
4. 修复后重跑整个相关测试文件。
5. 不要删除测试让 CI 通过。
6. 不要用 `sleep` 掩盖竞态。
7. 不要为通过测试放宽权限。

## 11. 阶段练习

### 练习 1：单元测试

给以下函数写测试：

- SHA-256 计算
- 文件大小校验
- 权限判断
- 幂等键生成

验收：

- 不依赖数据库。
- 覆盖成功和失败路径。
- 每个测试只验证一个行为。

### 练习 2：服务层测试

测试文档服务：

- 创建成功
- 重复指纹返回已有 Blob
- 唯一冲突
- 无权限

验收：

- 使用测试数据库。
- 每个测试独立造数。
- 测试结束后不污染其他数据。

### 练习 3：CI

搭建 GitHub Actions：

- PostgreSQL service
- 安装依赖
- 执行迁移
- 运行测试
- 输出覆盖率

验收：

- Pull request 能自动运行。
- 失败测试阻止合并。
- CI 密钥不暴露到日志。

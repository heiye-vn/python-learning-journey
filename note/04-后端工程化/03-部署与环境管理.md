# 部署与环境管理

本文面向 FastAPI + PostgreSQL 后端应用，目标是掌握从本地开发到生产部署的完整流程，并理解环境隔离、密钥管理、反向代理和发布策略。

## 1. 环境分层

| 环境 | 用途 | 数据 | 说明 |
|---|---|---|---|
| local | 本地开发 | 虚构数据 | 允许热重载和调试 |
| test | 自动化测试 | 每次重建 | 不保存业务数据 |
| staging | 预发布验证 | 脱敏或仿真数据 | 尽量接近生产 |
| production | 线上服务 | 真实数据 | 严格权限和审计 |

不要在生产环境执行实验性 SQL、手动改数据或直接调试。

## 2. 应用配置

使用 Pydantic Settings 管理配置：

``` python
from functools import lru_cache

from pydantic import PostgreSQLDsn, SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    environment: Literal["local", "test", "staging", "production"]
    database_url: PostgreSQLDsn
    jwt_private_key: SecretStr
    redis_url: str

    model_config = SettingsConfigDict(env_file=".env", env_file_encoding="utf-8")


@lru_cache
def get_settings() -> Settings:
    return Settings()
```

`.env.example`：

``` bash
ENVIRONMENT=local
DATABASE_URL=postgresql+asyncpg://app_user:change-me@localhost:5432/app
JWT_PRIVATE_KEY=
REDIS_URL=redis://localhost:6379/0
```

`.env` 只用于本地开发，并且必须加入 `.gitignore`。

## 3. Dockerfile

推荐多阶段构建：

``` dockerfile
FROM python:3.12-slim AS builder

ENV UV_COMPILE_BYTECODE=1
WORKDIR /app

COPY pyproject.toml uv.lock ./
RUN pip install --no-cache-dir uv && uv sync --frozen --no-install-project

COPY . .
RUN uv sync --frozen


FROM python:3.12-slim

RUN addgroup --system app && adduser --system --ingroup app app
WORKDIR /app

COPY --from=builder --chown=app:app /app/.venv /app/.venv
COPY --from=builder --chown=app:app /app /app

ENV PATH="/app/.venv/bin:$PATH" \
    PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1

USER app

EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

要点：

- 锁定依赖版本。
- 使用非 root 用户运行。
- 不要把 `.env`、密钥和本地文件复制进镜像。
- 生产不建议 `--reload`。

## 4. Docker Compose

``` yaml
services:
  app:
    build: .
    env_file: .env
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    command: >
      sh -c "alembic upgrade head &&
             uvicorn app.main:app --host 0.0.0.0 --port 8000"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 10s
      timeout: 3s
      retries: 5
    restart: unless-stopped

  postgres:
    image: postgres:17
    environment:
      POSTGRES_USER: app_user
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?required}
      POSTGRES_DB: app
    volumes:
      - postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app_user -d app"]
      interval: 10s
      timeout: 3s
      retries: 10
    restart: unless-stopped

  redis:
    image: redis:7
    command: redis-server --appendonly yes
    volumes:
      - redis-data:/data
    restart: unless-stopped

  nginx:
    image: nginx:1.27
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./deploy/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./deploy/certs:/etc/nginx/certs:ro
    depends_on:
      - app
    restart: unless-stopped

volumes:
  postgres-data:
  redis-data:
```

### 4.1 本地与生产差异

本地 Compose 可以挂载源码并开启热重载；生产镜像必须只读运行、固定版本、配置外部化。

``` yaml
# 只用于 local
services:
  app:
    command: uvicorn app.main:app --reload
    volumes:
      - ./app:/app/app
```

## 5. Nginx

``` nginx
worker_processes auto;

events {
    worker_connections 1024;
}

http {
    include mime.types;
    sendfile on;
    server_tokens off;

    upstream app_backend {
        server app:8000;
        keepalive 32;
    }

    server {
        listen 80;
        server_name example.com;

        location / {
            proxy_pass http://app_backend;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_read_timeout 60s;
        }
    }
}
```

生产应启用 HTTPS、HTTP/2、TLS 证书和合理超时。

## 6. Linux 服务

单机部署可以使用 systemd：

``` ini
[Unit]
Description=FastAPI backend
After=network.target postgresql.service

[Service]
Type=simple
User=app
Group=app
WorkingDirectory=/opt/app
EnvironmentFile=/etc/app/app.env
ExecStart=/opt/app/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=3

NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full

[Install]
WantedBy=multi-user.target
```

常用命令：

``` bash
sudo systemctl daemon-reload
sudo systemctl enable app
sudo systemctl start app
journalctl -u app -f
```

## 7. 迁移与发布

### 7.1 数据库迁移

``` bash
uv run alembic revision --autogenerate -m "create documents"
uv run alembic upgrade head
uv run alembic downgrade -1
```

发布规则：

- 迁移必须可以回滚或有前滚方案。
- 先部署兼容新结构的代码，再删除旧字段。
- 修改列类型前先确认数据兼容。
- 建索引用 `CONCURRENTLY`。
- 不要在业务高峰执行锁表迁移。

### 7.2 蓝绿与滚动发布

| 策略 | 优点 | 缺点 |
|---|---|---|
| 滚动发布 | 节省资源 | 需要版本兼容 |
| 蓝绿发布 | 快速回切 | 需要双倍资源 |
| 灰度发布 | 风险可控 | 需要路由和指标支持 |

上线前必须确认：

- 迁移可执行
- 健康检查通过
- 关键指标有监控
- 回滚路径明确
- 数据备份已完成

## 8. 日志轮转

uvicorn 输出标准输出后，由容器平台或 systemd 收集。

Docker 使用 `json-file` 限制大小：

``` json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "50m",
    "max-file": "5"
  }
}
```

systemd journal 自动轮转；文件日志需要 logrotate。

## 9. 健康检查

``` python
from fastapi import APIRouter

router = APIRouter()


@router.get("/health")
async def health() -> dict[str, str]:
    return {"status": "ok"}


@router.get("/ready")
async def ready() -> dict[str, str]:
    await check_database()
    await check_redis()
    return {"status": "ready"}
```

区别：

- `health` 表示进程是否存活。
- `ready` 表示是否可以接流量。

启动探针失败会重启容器；就绪探针失败只摘除流量。

- 依赖版本已锁定

## 11. 阶段练习

### 练习 1：本地 Compose

搭建：

``` text
FastAPI + PostgreSQL + Redis + Nginx
```

验收：

- 一条命令启动。
- 迁移自动执行。
- 健康检查通过。
- 应用容器不以 root 运行。

### 练习 2：生产镜像

构建并运行生产镜像。

验收：

- 镜像可重复构建。
- 依赖来自 lock 文件。
- 容器内没有 `.env`。
- 服务由非 root 用户启动。

### 练习 3：回滚

模拟一次发布失败。

验收：

- 应用可回滚。
- 数据库迁移有回滚或前滚方案。
- 回滚后关键接口可用。
